# تحديث السيرفر وقاعدة البيانات

اضبط `DATABASE_URL` في بيئة السيرفر على قاعدة البيانات المطلوبة، ثم شغّل:

```bash
npm ci
npm run build
npm start
```

عند استخدام PM2، أعد تحميل التطبيق بعد نجاح البناء بدل `npm start`.
ملف `deploy/deploy.sh` ينفّذ هذه الخطوات ويعيد تحميل PM2 بعد نجاحها.
تحتاج مرحلة البناء إلى حزم التطوير أيضًا؛ لا تستخدم `npm ci --omit=dev` قبل البناء.

## ماذا ينفّذ build؟

1. يفحص وجود صور الأقسام المطلوبة قبل إجراء أي تعديل على قاعدة البيانات.
2. يشغّل `prisma migrate deploy` لتطبيق ملفات التحديث المعلّقة بالترتيب.
3. يشغّل `prisma generate` ثم `next build`.

يشمل التحديث الجديد شجرة التصنيفات والتسميات وروابط الصور الأصلية الـ29.
يحافظ على معرّفات التصنيفات الموجودة وروابطها بالمنتجات، ولا ينسخ المنتجات
من جهاز التطوير إلى السيرفر. الملفات الأقدم المعلّقة تطبّق تحديثات بنية الجداول.
يسجّل Prisma كل تحديث بعد نجاحه، فلا يعاد تطبيق تحديث التصنيفات مع كل build.
إذا فشل تحديث قاعدة البيانات، يتوقف البناء ولا يعاد تشغيل التطبيق بواسطة deploy.sh.
إذا نجح تحديث قاعدة البيانات ثم فشل البناء، يبقى تحديث قاعدة البيانات مطبّقًا.

ارفع المشروع كاملًا، بما فيه:

- `prisma/schema.prisma` و`prisma/migrations/` بجميع الملفات الأصلية.
- `scripts/prepare-build.mjs`.
- `data/catalog-category-assets.json` و`public/categories/`.

خذ نسخة احتياطية من قاعدة السيرفر قبل أول ترقية. استخدم حساب قاعدة بيانات
يمتلك صلاحيات تعديل البنية. لا تعدّل محتوى migration سبق تطبيقه.

## فحص الملفات دون تعديل قاعدة البيانات

```bash
npm run build:check
```

لتطبيق التحديثات وحدها دون بناء الواجهة:

```bash
npm run db:deploy
```

## قاعدة قديمة بدون سجل migrations أو تحديث سابق فاشل

التشغيل التلقائي مخصص لقاعدة تتبع سجل migrations الخاص بهذا المشروع.
إذا ظهر `P3005` فهناك جداول موجودة دون سجل Prisma مطابق؛ يلزم فحص البنية
وتجهيز baseline يطابق حالتها الفعلية مرة واحدة قبل النشر.
إذا ظهر `P3009` فهناك تحديث سابق فاشل؛ افحص سجل الفشل وأصلح سببه أولًا.
لا تسجّل تحديثات كأنها مطبّقة دون مطابقة البنية، ولا تستخدم `migrate reset`
أو `db push --accept-data-loss` على قاعدة السيرفر.

### تحديث التصنيفات القديم وعمود imageUrl

الملف `20261015110000_complete_content_metadata` يضيف حقول الصور وSEO
والمحتوى التي كانت ناقصة من سجل التحديثات، ويعمل قبل تحديث التصنيفات.
إذا فشل `20261015120000_restore_source_category_catalog` سابقًا تحديدًا بسبب
عمود `Category.imageUrl` المفقود، وتأكدت أن المحاولة توقفت وتراجعت معاملتها، نفّذ:

```bash
npx prisma migrate resolve --rolled-back 20261015120000_restore_source_category_catalog
npm run build
```

لا تحتاج هذه الخطوة إذا كانت حالة قاعدة البيانات محدثة أو سبق إصلاح سجل الفشل.
يجب رفع التحديث الجديد وملفات package.json وpackage-lock.json قبل إعادة نشر Vercel.

مرجع Prisma: https://www.prisma.io/docs/orm/prisma-migrate/workflows/baselining
